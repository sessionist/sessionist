# Agent guide

For coding agents working in this repository.

Using Sessionist does not require this repo: `npx sessionist` installs and runs it, and
[llms.txt](llms.txt) is the usage guide. Everything below is for changing the code.

## What this is

A local OpenTelemetry sink a coding agent can read. An agent's OTLP exporter points at
`localhost`; Sessionist stores every run as a session in SQLite and exposes it to coding
agents over a read-only MCP server, to people in a web viewer, and to files as a portable
session artifact. It reads one wire format, the current OpenTelemetry GenAI semantic
conventions, and adapts to no framework.

## Rules that bind code

- **Never invent data.** A field absent from the telemetry is absent. No placeholder values,
  no defaulted counts, no synthesized timestamps.
- **Never drop data.** Unrecognized spans and attributes are preserved verbatim as
  passthrough events.
- **Sessions are immutable.** No code path edits, reorders, or deletes committed events.
  Derived data goes in the `annotations` table under a namespaced source.
- **No telemetry, no gates.** No phone-home, analytics, accounts, license checks, or upsell
  UI. The only permitted outbound call is an update check against the npm registry, at most
  daily, disableable. `--offline` disables all egress.
- **Core knows wire formats, not clients.** Nothing recognizes or special-cases a particular
  framework, prompt template, or chat client.
- **No content policy.** Nothing inspects, filters, or restricts what a session contains.
- **The HTML export makes zero network requests.** One file, no external scripts, fonts, or
  fetches; the test suite opens it under a blackholed resolver to prove it.
- **MCP mirrors the Query API.** Tools are read-only and stay at one-to-one parity with
  `src/api/query.ts`; no new tool without a reason.
- **License headers** (`MIT`) on every source file; the whole repository is MIT.
  The mark is unregistered: never emit (R) or claim registration, and never grant the name or
  mark in code or docs; TRADEMARK.md governs them.

## Layout

```
src/receiver    OTLP endpoint (protobuf and JSON)
src/normalize   dialects; one file each, registered in index.ts
src/assemble    session grouping
src/store       SQLite schema, migrations, blob spillover
src/api         Query API, the only read path
src/mcp         MCP server over the Query API
src/exporters   session-file, session-html, eval-generic
src/cli         commands, setup, service
src/service     start-at-login units (launchd, systemd --user)
skills/         the sessionist-connect skill, shipped in the package
player/         React viewer; talks to the Query API only
fixtures/spec   test corpus, generated — never edit by hand
tools/spec-emitter  generates the corpus from the pinned conventions
```

Dialects and exporters are registries: a small interface, a directory of implementations,
an index that registers them. Adding one never requires editing core pipeline code.

## Commands

```
npm install
npm run typecheck
npm test            # headers, server build, full suite
npm run build       # CLI + viewer + skill into dist/
npm run fixtures    # regenerate fixtures/spec from tools/spec-emitter
npm run dev -- …    # run the CLI from source
```

## Testing

- The specification is the oracle. The corpus under `fixtures/spec/` is generated by the spec
  emitter from the pinned conventions commit; adding a convention feature means adding a
  scenario, regenerating, and stating the expected reading in `tests/normalize.test.ts`.
  [fixtures/README.md](fixtures/README.md) documents the layout, every scenario, and the
  regeneration rules; the corpus is MIT like everything else, so other tools can test against it.
- Hand-assembled OTLP bytes are forbidden; the SDK encodes.
- Framework recordings are not test inputs. If a framework deviates from the convention,
  file an issue against the framework; never change the reader to fit it.
- The fidelity property must hold over every scenario; the malformed batches must degrade
  gracefully; the session file and HTML export must round-trip byte-equal.
- Tests never touch the developer's machine: no real `claude` CLI, no real `launchctl`, no
  writes outside a temp directory.

## Comments

One-sentence file headers. Comments state a technical constraint a maintainer needs, in one
or two lines; no history, no rationale essays, no references to planning documents.

## Definition of done

`npm run typecheck` and `npm test` pass. No new runtime dependency without a stated reason.
Any change to the session file format, the Query API shapes, or the annotations model is a
public-contract change: flag it, never slip it in.

## Do not touch without asking

- `fixtures/spec/` by hand (regenerate), `tools/spec-emitter/schema/` (re-pinning the
  conventions is its own deliberate commit), `src/receiver/otlp/gen/` (generated).
- `LICENSE`, `TRADEMARK.md`, `package.json` publish fields.
